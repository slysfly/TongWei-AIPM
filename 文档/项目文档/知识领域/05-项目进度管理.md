# 05 · 项目进度管理（Project Schedule Management）

> 过程（6 个）：6.1 规划进度管理 | 6.2 定义活动 | 6.3 排列活动顺序 | 6.4 估算活动持续时间 | 6.5 制定进度计划 | 6.6 控制进度

## 1. 概述

进度管理是项目的核心基线之一。系统通过**任务计划/实际日期**、**依赖关系（FS/FF/SS/SF）**、**里程碑**、**Sprint**、**甘特图服务**及 **EVM 进度偏差** 实现全过程进度管理。

## 2. 系统实现

### 2.1 规划进度管理（6.1）

- `Project.project_type` 决定方法论（agile → Sprint 迭代、waterfall → 关键路径、hybrid → 混合）。
- `Project.settings` 可配置进度核算方式：EVM / 里程碑进度 / 工时进度。

### 2.2 定义活动（6.2）

- `Task` — 活动工作包，`level` 标注 WBS 层级深度。
- `RecurringTask` — 重复型活动（日常巡检、定期报告），由 `recurring_task_scheduler.py` 定期生成实例。
- `ScheduledJob` — 定时任务（如日报自动生成），由 `scheduler_service` 管理。

### 2.3 排列活动顺序（6.3）

- `TaskDependency` — 四种依赖类型：
  - FS (Finish-to-Start)：最常用，前序完成后续才开始
  - FF (Finish-to-Finish)：前序完成后续才能完成
  - SS (Start-to-Start)：前序开始后续可开始
  - SF (Start-to-Finish)：前序开始后续才能完成
- `lag_time`（延迟天数）支持提前/滞后。
- `dependencies_from` / `dependencies_to` 双向关系。

### 2.4 估算活动持续时间（6.4）

- `Task.estimated_hours`：工时估算。
- AI 辅助：`POST /ai/generate-wbs` 时 AI 可自动估算。

### 2.5 制定进度计划（6.5）

- **甘特图**：`gantt_service.py` 计算任务时间线、依赖链、关键路径。
- **里程碑**：`Milestone` 标注关键节点（`due_date`、`status`）。
- **Sprint**：`Sprint` + `SprintTask`，适配敏捷迭代。
- **Release**：`Release` + `ReleaseTask`，版本发布进度。

### 2.6 控制进度（6.6）

- **EVM 进度偏差**：`EVMSnapshot.schedule_variance` (SV = EV − PV)、`schedule_performance_index` (SPI = EV / PV)。
- 基线对比：`baseline_start / baseline_end` vs 实际 `start_date / end_date`。
- 审计日志：进度变更记录于 `AuditLog`。
- Webhook/自动化：进度偏差超阈 → 触发告警。

## 3. 关键数据模型

- `Task` — `planned_start/end`、`actual_start/end`、`estimated_hours`、`actual_hours`
- `TaskDependency` — `predecessor_id`、`successor_id`、`dependency_type`、`lag_time`
- `Milestone` — 里程碑；`due_date`、`status`、`gate_criteria`
- `Sprint / SprintTask` — 迭代排期
- `Release / ReleaseTask` — 版本发布计划
- `RecurringTask / RecurringTaskInstance` — 重复任务
- `ScheduledJob / JobExecutionLog` — 定时任务
- `EVMSnapshot` — 进度偏差指标 (SV/SPI)

## 4. 对应 API

| 路由 | 说明 |
|------|------|
| /tasks | 活动 CRUD |
| /sprints | Sprint 排期 |
| /releases | 版本发布 |
| /recurring-tasks | 重复任务管理 |
| /scheduled-jobs | 定时任务管理 |
| /ai/generate-wbs | AI 生成 WBS + 进度 |
| /gantt (implied) | 甘特图数据 |
| /evm (implied) | EVM 进度偏差 |

## 5. 进度基线管理

- 变更后若需更新基线：通过审批流程 → 更新 `baseline_start/baseline_end`。
- 每个 `EVMSnapshot.snapshot_date` 记录截面数据，用于趋势分析。
