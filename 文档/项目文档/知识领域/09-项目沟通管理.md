# 09 · 项目沟通管理（Project Communications Management）

> 过程（3 个）：10.1 规划沟通管理 | 10.2 管理沟通 | 10.3 监督沟通

## 1. 概述

沟通管理确保干系人及时获取准确信息。系统提供**站内通知中心**、**消息/频道**、**WebSocket 实时推送**、**邮件**、**集成 IM（飞书/企微/钉钉/Slack）** 以及 **评论协作**。

## 2. 系统实现

### 2.1 规划沟通管理（10.1）

- `Notification` — 站内通知模板与发送规则。
- `Integration` 配置外部 IM 的 webhook/API 凭证。
- 通知偏好：用户在 `settings` 中设定通知频率与渠道（站内/邮件/IM）。
- 沟通计划文档可通过 `Wiki` 发布。

### 2.2 管理沟通（10.2）

| 沟通渠道 | 系统功能 | 数据模型 |
|----------|----------|----------|
| 站内通知 | 通知中心；任务/项目变更自动生成 | `Notification` |
| 消息即时通讯 | 频道（Channel）+ 成员 + 回复（MessageReaction） | `Message`、`Channel`、`ChannelMember` |
| WebSocket 实时 | 实时推送任务/项目状态变更 | `ws` 路由（`websocket.py`） |
| 邮件 | SMTP 发送日报/周报/事件通知 | `email.py`（core 模块） |
| 集成 IM | 飞书/企微/钉钉/Slack 消息推送 | `integrations/` 各适配器 |
| 评论 | 任务级讨论 | `Comment` |
| Wiki 评论 | 知识页面讨论 | `WikiComment` |

### 2.3 监督沟通（10.3）

- 通知送达状态：`Notification` 记录已读/未读。
- 集成连接状态：OAuth 凭证校验（未配置时返回明确错误）。
- 邮件投递状态：SMTP 失败时优雅降级并记录告警日志。
- 报表：`/reports` 提供沟通覆盖率统计。

## 3. 关键数据模型

- `Notification` — 站内通知（类型、内容、目标用户、已读状态）
- `Message / Channel / ChannelMember / MessageReaction` — 即时消息
- `Comment` — 任务评论
- `WikiComment` — Wiki 页面评论
- `Integration` — 外部 IM 集成配置

## 4. 对应 API

| 路由 | 标签 | 说明 |
|------|------|------|
| /notifications | 通知管理 | 站内通知查询/标记已读 |
| /messages | 消息管理 | 频道消息 CRUD |
| /comments | 评论管理 | 任务评论 |
| /integrations | 集成管理 | 外部 IM 集成 |
| /wiki/* | Wiki知识库 | Wiki 评论 |
| /ws | WebSocket | 实时推送 |
| /reports | 报表 | 沟通报表 |

## 5. 沟通矩阵（示例）

| 沟通类型 | 发送方 | 接收方 | 频率 | 渠道 |
|----------|--------|--------|------|------|
| 任务分配 | 系统 | 任务负责人 | 事件驱动 | 站内通知 + 集成 IM |
| 进度日报 | 系统 | 项目经理 | 每日 | 邮件 + 站内通知 |
| 风险告警 | 系统 | 风险管理人 | 事件驱动 | 站内通知 + 微信/企微 |
| 里程碑完成 | 系统 | 全部干系人 | 事件驱动 | 站内通知 + Webhook |
| 变更审批 | 审批流 | 审批人 | 事件驱动 | 站内通知 + 邮件 |
| 团队讨论 | 成员 | 频道成员 | 实时 | WebSocket + 消息频道 |
