# 04 · 项目范围管理（Project Scope Management）

> 过程（6 个）：5.1 规划范围管理 | 5.2 收集需求 | 5.3 定义范围 | 5.4 创建 WBS | 5.5 确认范围 | 5.6 控制范围

## 1. 概述

范围管理确保系统只包含必要的工作。通维AIPM 通过**项目 → Epic → 任务层级**、**WBS 自动生成**、**自定义字段**与**表单**来覆盖需求→范围→WBS 全链路。

## 2. 系统实现

### 2.1 规划范围管理（5.1）

- `Project.settings` 中可定义范围管理配置。
- `ProjectType`：agile/waterfall/hybrid/kanban → 影响 WBS 分解策略。

### 2.2 收集需求（5.2）

- **自定义字段**：`CustomField` + `CustomFieldValue`，支持为项目/任务定义任意扩展字段。
- **表单**：`FormTemplate` → `FormSubmission`，可创建结构化需求采集表单。
- **Wiki**：需求文档可写为 Wiki 页面。

### 2.3 定义范围（5.3）

- `Project` 实体：`name`、`description`、`industry_type`（IT/建筑/制造/金融等 9 种）、`start_date`、`end_date`。
- **Epic**：`Epic` + `EpicTask` → 大型需求 → 分解为多个任务。

### 2.4 创建 WBS（5.4）★ 本系统核心能力

- **AI 生成 WBS**：`POST /ai/generate-wbs` → 自然语言输入 → 自动产出结构化 WBS。
  - 回写 `tasks` 表（含 `wbs_code`：如 "1.1.2"、`level`、`parent_task_id`）。
  - 同时生成关联 `risks`。
- **任务模板**：`TaskTemplate`，复用标准工作包。
- **手动 WBS**：`POST /tasks` + `parent_task_id` 手动构建层级。

### 2.5 确认范围（5.5）

- 里程碑阶段门：`Milestone.gate_criteria`(JSON) + `approval_required`。
- 审批引擎：`ApprovalFlow` → 范围交付物验收审批。
- 任务状态 `in_review` → 评审完成进入 `done`。

### 2.6 控制范围（5.6）

- **范围基线**：`Project.baseline_start/baseline_end`、`Task` 的 `planned_*` 字段。
- **合规审计**：`ComplianceAudit` 可审计范围变更记录。
- 审计日志 `AuditLog` 记录 scope 变更。

## 3. 关键数据模型

- `Project` — 范围说明书容器
- `Task` — WBS 工作包；`wbs_code`、`level`、`parent_task_id` 构成层级树
- `Epic / EpicTask` — 大型需求分解
- `CustomField / CustomFieldValue` — 需求扩展字段
- `FormTemplate / FormSubmission` — 需求采集
- `TaskTemplate` — 标准范围模板
- `Milestone` — 范围确认阶段门
- `ComplianceControl` — 范围控制检查点

## 4. 对应 API

| 路由 | 说明 |
|------|------|
| POST /ai/generate-wbs | AI 生成 WBS（核心） |
| /projects | 项目 CRUD |
| /tasks | 任务 CRUD（含层级） |
| /epics | Epic 管理 |
| /custom-fields | 自定义字段 |
| /forms | 表单模板与提交 |
| /task-templates | 任务模板 |
| /approvals | 范围审批 |

## 5. 范围 vs 产品范围

- **项目范围**：构建通维AI PM 平台（包括 API + 前端 + Docker 部署包 + 文档）。
- **产品范围**：平台的功能属性——支持组合/项目/任务管理、AI-WBS、EVM、风险等。本项目范围在产品需求（`forms`/`custom_fields`/`Wiki`）中定义并经由 `Task` 完成交付。
