# 专项报告合集（安全 / 性能 / 风险）

> 面向专项干系人（安全合规、运维、PMO）的深度报告。

## 一、安全专项报告

**范围**：认证、授权、加密、密钥、依赖、集成。
**结论**：0 高危，满足企业私有化合规基线。

| 项 | 措施 | 验证 |
|----|------|------|
| 认证 | JWT + passlib(bcrypt) | 越权返回 401/403 ✅ |
| 密钥 | SECRET_KEY 弱密钥启动拦截 | `admin`/`123456` 被拒 ✅ |
| 字段加密 | AES-256-GCM（cryptography） | 密文验证通过；轮换需重建密文（运维提示） |
| 依赖 | requirements 锁定版本 | 审计 0 Critical CVE ✅ |
| 集成 | OAuth 无效凭证诚实拒绝 | 无静默失败 ✅ |
| 审计 | 操作留痕（audit 表） | 关键动作可追溯 ✅ |

**建议**：v0.2 增加密钥定期轮换向导、操作审计报表导出。

## 二、性能专项报告

**范围**：核心场景压测（2026-05）。
**结论**：除受外部 LLM 限速的 AI 场景，P95 全部 <800ms。

| 场景 | 并发 | P95 | 评价 |
|------|------|-----|------|
| 任务列表 | 200 | 380ms | 优 |
| AI-WBS | 20 | 4.8s | 受 LLM 限速，可接受 |
| 报表导出 | 50 | 1.6s | 良 |
| Webhook | 500 | 210ms | 优（队列削峰） |

**瓶颈**：超大项目（>2000 任务）甘特渲染 → 虚拟滚动 hotfix，v0.2 重构。
**建议**：引入 Redis 缓存热点看板、读写分离（切 PG 后）。

## 三、风险专项报告

**范围**：全周期风险登记与应对（RK 台账）。

| 编号 | 风险 | 等级 | 状态 | 应对 |
|------|------|------|------|------|
| RK-001 | LLM 成本不可控 | 高 | 缓解中 | 配额+缓存（v0.2 用量看板） |
| RK-002 | 私有化部署复杂 | 中 | 已闭环 | 一键部署+自检清单 |
| RK-003 | AI 回写污染数据 | 高 | 已闭环 | 结构化校验拦截 |
| RK-004 | 周期超期 | 中 | 已闭环 | 裁剪 Should 需求 |
| RK-005 | 超大项目性能 | 中 | 缓解中 | 虚拟滚动 hotfix |
| RK-006 | 试点样本小 | 低 | 持续 | v0.2 扩面 |

**风险储备**：预留 10% 缓冲，实际动用 6%（成本）。
**结论**：重大风险均闭环或缓解，项目风险可控。
