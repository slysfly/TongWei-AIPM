# 13 · 启动过程组（Initiating Process Group）

> 过程（2 个）：4.1 制定项目章程 | 13.1 识别干系人
>
> 启动过程组定义新项目或新阶段的开始，获得授权。

---

## 1. 本过程组在系统中的体现

通维AI PM 系统本身作为一个**项目管理工具平台**，它的"启动"描述的是**使用该工具管理一个项目**的过程，同时也覆盖系统自身的初始化启动。

## 2. 制定项目章程（4.1）

### 系统自身初始化

| 步骤 | 发生时机 | 系统实现 |
|------|----------|----------|
| 环境检测 | 容器启动/应用启动 | `settings.ENVIRONMENT` 检查；`SECRET_KEY` 弱密钥检测（生产拒绝启动） |
| 数据库初始化 | `lifespan` start | 自动 `create_all` 或 Alembic `upgrade head` |
| 初始管理员创建 | 首次启动 | `init_admin.py` 按 `INITIAL_ADMIN_*` 环境变量创建超级用户 |
| 后台服务启动 | `lifespan` start | scheduler / worker / recurring loop 异步启动 |
| 集成连接检查 | 启动时 + 按需 | OAuth 凭证校验 |

### 使用系统创建项目（项目章程数字化）

用户通过 `POST /projects` 创建项目，即完成 4.1 过程：

```json
{
  "name": "项目名称",
  "description": "项目章程描述",
  "industry_type": "it_software",
  "project_type": "agile",
  "priority": 1,
  "start_date": "2026-01-01",
  "end_date": "2026-06-30",
  "budget": 1000000,
  "owner_id": "用户UUID"
}
```

- 系统自动分配 `Project.id` (UUID) 作为正式授权标识。
- 里程碑自动创建（如首个里程碑 = 立项通过）。

## 3. 识别干系人（13.1）

### 系统初始干系人

| 干系人 | 创建方式 | 系统实体 |
|--------|----------|----------|
| 系统管理员 | 自动创建（INITIAL_ADMIN） | `User(is_superuser=True)` |
| 项目经理 | 项目创建时指定 | `Project.owner_id` |
| 项目成员 | 通过 `/members` 添加 | `ProjectMember` |

### 项目中识别干系人

- `POST /members` — 添加干系人并赋予角色。
- `GET /members` — 干系人清单。
- `User.search` — 按姓名/邮箱搜索潜在干系人。

## 4. 启动过程组产出物

| 交付物 | 系统对应 |
|------------|----------|
| 项目章程 | `Project` (name/desc/date/budget/owner) |
| 干系人登记册 | `User` + `ProjectMember` + `Role` |
| 项目授权 | `Project.id` (UUID) + JWT token (用户认证) |

## 5. 系统架构启动顺序

```
1. 容器/服务启动
2. settings 环境检测（key/crypto 检查）
3. 数据库迁移（create_all 或 alembic）
4. 初始管理员创建（如无）
5. scheduler_service.start()
6. worker_manager.start_all()
7. recurring_task_loop (async)
8. FastAPI lifespan ready
9. 用户登录（/auth/login）→ JWT
10. 创建项目（/projects）→ 项目章程生效
```
