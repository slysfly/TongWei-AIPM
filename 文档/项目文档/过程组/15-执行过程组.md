# 15 · 执行过程组（Executing Process Group）

> 过程——整合：4.3 指导与管理 | 质量：8.2 | 资源：9.3–9.5 | 沟通：10.2 | 风险：11.6 | 采购：12.2 | 干系人：13.3
>
> 执行过程组完成规划确定的工作，满足项目要求。

---

## 1. 本过程组在系统中的体现

系统的执行层由 **AI 执行主体** + **自动化引擎** + **人工操作** 三部分协同推进。

## 2. 各执行过程

### 2.1 指导与管理项目工作（4.3）★ 本系统核心

| 执行活动 | 系统实现 | 触发方式 |
|----------|----------|----------|
| AI WBS 生成 → 回写 tasks/risks | `POST /ai/generate-wbs` | 用户请求 |
| 多 Agent 协同执行 | `multi_agent` 模块 + `ai_agent` session | AI 自主执行 |
| 自动化规则触发 | `automation_engine.py` 事件 → 通知/邮件/Webhook | 任务/项目状态变更 |
| 后台队列处理 | `queue_worker.py` → 异步邮件/通知/报表 | 事件排队的异步消费 |
| 定时任务执行 | `scheduler_service` → 定期报告/批处理 | cron-like 调度 |
| 重复任务实例化 | `recurring_task_scheduler.py` → 按规则生成实例 | 每分钟循环检查 |

### 2.2 管理质量（8.2）

- 执行合规审计：`ComplianceAudit` 按计划执行质量检查
- 测试执行：pytest 运行自动化测试套件
- 审批流执行：`ApprovalInstance` → `ApprovalStep` 逐级推进

### 2.3 获取资源（9.3）

- 资源分配：`POST /resource-allocations` 分配资源到任务
- 项目成员：`POST /members` 添加团队成员
- 集成连接：OAuth 授权码交换获取访问令牌

### 2.4 建设团队（9.4）

- 团队沟通：频道消息 (`/messages`) + 实时 WebSocket
- 知识分享：Wiki 协作编辑，RAG 知识库文档上传
- 集成 IM：飞书/企微/钉钉群同步

### 2.5 管理团队（9.5）

- 任务分配与进度跟踪
- 评论协作（`Comment`）
- 冲突管理（资源分配检查）

### 2.6 管理沟通（10.2）

| 沟通类型 | 执行方式 |
|----------|----------|
| 事件通知 | 自动化引擎 → Notification 表 → 站内+推送 |
| 日报周报 | `report_service.py` → 生成 PDF + 发送邮件 + 站内通知 |
| 审批请求 | 审批流 → 通知审批人 → 提醒（站内+邮件+IM） |
| 风险告警 | 风险状态变更 → 通知负责人 |

### 2.7 实施风险应对（11.6）

- 风险应对任务创建（通过自动化规则）
- 风险状态更新：identifying → mitigating → closed
- AI 辅助风险分析查询

### 2.8 实施采购（12.2）

- LLM API 调用（运行时按配置路由到对应 Provider）
- 集成连接建立（OAuth 流程）
- Webhook 回调触发

### 2.9 管理干系人参与（13.3）

- 仪表盘发布项目关键数据
- 按角色推送不同级别信息
- 审批委托执行

## 3. 执行流水线（Pipeline）

```
用户/时间触发
    ↓
API 请求 / 事件
    ↓
自动化引擎匹配规则
    ↓
AI Agent 决策/执行
    ↓
数据库写入 + 审计日志
    ↓
通知投递（站内/邮件/IM/Webhook）
    ↓
干系人响应
```

## 4. 后台常驻服务

| 服务 | 模块 | 职责 |
|------|------|------|
| Scheduler Service | `scheduler_service.py` | 定时/周期任务调度 |
| Queue Worker | `queue_worker.py` | 异步消息/邮件/报表处理 |
| Recurring Task | `recurring_task_scheduler.py` | 重复任务每分钟检查执行 |
| WebSocket Handler | `websocket.py` | 实时状态推送 |
