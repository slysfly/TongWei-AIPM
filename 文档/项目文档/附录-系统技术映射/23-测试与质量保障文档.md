# 23 · 测试与质量保障文档

> 质量管理体系的技术实现附录。覆盖测试策略、测试覆盖范围、CI 集成、Bug 追踪。

---

## 1. 测试总体策略

| 层级 | 类型 | 工具 | 目标 |
|------|------|------|------|
| 单元测试 | 后端函数级 | pytest | 认证/CRUD/MCP/自动化/Webhook/集成/AI降级 |
| 集成测试 | API 端到端 | pytest + httpx | 路由正确性、数据库事务 |
| 安全测试 | 权限验证 | pytest + JWT mock | RBAC 权限隔离 |
| AI 降级测试 | 异常路径 | pytest mock | Provider 不可用时优雅降级 |

## 2. 测试套件详情（backend/tests/）

### 2.1 测试文件结构

```
backend/tests/
  ├── test_auth.py           ← 用户认证/注册/登录/权限
  ├── test_projects_tasks.py   ← 项目/任务 CRUD 操作
  ├── test_mcp.py            ← MCP 协议工具/资源 API
  ├── test_automation_webhook.py ← 自动化规则引擎 + Webhook 事件投递
  ├── test_integrations_ai.py  ← 集成 AI 联动
  ├── test_integrations.py   ← 外部集成 OAuth 流程
  └── test_ai_service.py      ← AI 服务 / Provider 降级
```

### 2.2 测试覆盖范围

| 测试目标 | 覆盖内容 | 知识领域关联 |
|----------|----------|-------------|
| 认证 | JWT 生成/验证、密码哈希(bcrypt)、token 刷新 | 干系人管理 |
| CRUD | 项目/任务的创建/更新/删除/查询，字段校验 | 整合/范围/成本 |
| MCP | 工具调用（create_project/create_task） | 整合/采购 |
| 自动化 | 事件→规则→通知/邮件/Webhook 链路 | 整合/沟通 |
| Webhook | 事件投递、重试、签名校验 | 采购/沟通 |
| 集成 | OAuth 流程、凭据校验、错误处理 | 采购 |
| AI 降级 | Provider 不可用时返回 503 + 提示 | 采购/风险 |

### 2.3 测试配置

```ini
# backend/pytest.ini
[pytest]
testpaths = tests
```

- 自动使用独立 SQLite 测试库（不影响生产数据）
- 环境变量 `ENVIRONMENT=test` 隔离测试配置

## 4. 测试执行方式

```bash
cd backend
pytest                        # 运行全部测试
pytest tests/test_auth.py     # 单独文件
pytest -v                     # 详细输出
pytest --coverage             # 代码覆盖率（需安装 pytest-cov）
```

## 5. 质量门禁（Quality Gates）

| 门禁 | 标准 | 违反后果 |
|------|------|----------|
| 单元测试通过 | pytest exit code = 0 | 阻断部署 |
| 慢查询告警 | API 响应 ≥500ms | 监控告警 |
| 安全密钥 | 生产环境 SECRET_KEY 强度 | 拒绝启动 |
| 审批流 | 变更必须审批 | 不可更新基线 |
| 合规审计 | 定期审计未完成 | 质量报告标记 |

## 6. Bug / 缺陷追踪

系统自身未内置 Bug 追踪模块，但可通过以下方式管理：

| 方式 | 说明 |
|------|------|
| GitHub Issues | 集成 GitHub OAuth 后关联 Issue 追踪 |
| 任务系统 | 在 `tasks` 中创建 Bug 类型的任务 |
| 通知 | Bug 创建触发自动化规则通知相关人员 |
| 报表 | 缺陷统计可通过 `/reports` 生成 |

## 7. 持续改进（QM 循环）

```
计划 → 制定测试策略 / 合规控制
  ↓
执行 → pytest 自动化测试 / 合规审计执行
  ↓
检查 → 测试报告 / 合规审计结论 / 监控指标
  ↓
处理 → Bug 修复 / 合规整改 / 测试补充
  ↓ (下一轮循环)
再计划……
```
