# 22 · 部署运维与配置管理

> 配置管理 + 运维实践。覆盖部署方式、环境配置、数据库迁移、安全清单、监控告警。

---

## 1. 部署方式对比

| 特性 | Docker Compose（推荐） | 源码部署 |
|------|-----------------------|----------|
| 复杂度 | 低（一行命令） | 中 |
| 数据库 | PostgreSQL 15（自动） | PostgreSQL 或 SQLite |
| Redis | 自动 | 需自行配置 |
| 前端 | 多阶段构建 | 需 Node.js 构建 |
| 适用 | 生产环境 | 开发/私有部署 |

### 1.1 Docker Compose 部署（推荐）

```bash
cp .env.example .env
# 编辑 .env: SECRET_KEY, INITIAL_ADMIN_PASSWORD, SMTP_* 等
docker compose up -d --build
```

服务结构：
- `backend` (FastAPI) :8000
- `db` (PostgreSQL 15) :5432
- `redis` (Redis 7) :6379

### 1.2 源码部署

```bash
# 后端
cd backend
python -m venv .venv && .venv\Scripts\activate  # Windows
pip install -r requirements.txt
pip install -r requirements-dev.txt
alembic upgrade head  # 生产数据库迁移
python serve.py       # 默认端口8000

# 前端（可选）
cd frontend
npm install
npm run build  # 产物在 frontend/dist
```

## 2. 环境变量配置（config.py）

| 变量 | 默认值 | 说明 | 关联 |
|------|--------|------|----------|
| `SECRET_KEY` | (空) | JWT 签名密钥（生产强制强随机） | 整合管理(安全) |
| `ENVIRONMENT` | development | production/development/test | 整合管理(配置) |
| `DATABASE_URL` | sqlite:///./dev.db | 数据库连接串 | 整合管理(数据) |
| `REDIS_URL` | redis://localhost:6379/0 | 缓存/队列 | 整合管理(基础设施) |
| `DB_MIGRATE` | 1 | 1=Alembic升级；0=create_all兜底 | 质量管理 |
| `SMTP_*` | (空) | 邮件配置(HOST/PORT/USER/PASS) | 沟通管理 |
| `INITIAL_ADMIN_*` | admin/admin123/... | 初始管理员 | 干系人管理 |
| `*_API_KEY` | (空) | 各 AI Provider 密钥 | 采购管理 |
| `ZAPIER_WEBHOOK_SECRET` | (空) | Zapier 签名密钥 | 采购管理 |
| `VERSION` | v0.1 | 系统版本 | 整合管理(配置) |

## 3. 数据库迁移（Alembic）

| 操作 | 命令 | 说明 |
|------|------|------|
| 生成迁移 | `alembic revision --autogenerate -m "描述"` | 模型变更后 |
| 升级 | `alembic upgrade head` | 更新到最新 schema |
| 回滚 | `alembic downgrade -1` | 回退一步 |
| 历史 | `alembic history` | 查看迁移历史 |

迁移脚本位于 `backend/alembic/versions/`，纳入版本控制。

## 4. 生产安全清单

| # | 检查项 | 说明 |
|---|--------|------|
| [ ] | SECRET_KEY | 设为强随机值（`openssl rand -hex 32`） |
| [ ] | ENVIRONMENT=production | 生产模式启用更严格检查 |
| [ ] | 初始管理员密码 | 修改 `INITIAL_ADMIN_PASSWORD` 为强密码 |
| [ ] | HTTPS | 通过 Nginx/Caddy 反向代理终止 TLS |
| [ ] | SMTP 配置 | 配置邮件通知，未配置时优雅失败 |
| [ ] | AI API Key | 至少配置一个 Provider |
| [ ] | 集成 OAuth 凭证 | 按需配置 IM/GitHub/Zoom 凭证 |
| [ ] | 数据库密码 | PostgreSQL 强密码 + 网络隔离 |
| [ ] | Redis 密码 | 生产必须设置密码 |
| [ ] | 文件上传限制 | `uploads/` 目录权限控制 |

## 5. 监控与告警

### 5.1 内置监控

| 监控项 | 实现 | 阈值 |
|--------|------|------|
| API 响应时间 | `MonitoringMiddleware` + `X-Process-Time` | ≥500ms = 慢查询 |
| 请求量/错误率 | `metrics_collector` | — |
| 系统健康 | `GET /health` | status + version + timestamp |
| 审计日志 | `AuditLog` (所有变更) | — |

### 5.2 外部监控推荐

- 应用指标：Prometheus + Grafana
- 日志聚合：ELK / Loki + Grafana
- 错误追踪：Sentry
- Uptime：UptimeRobot 或同类服务

## 6. 性能优化策略

| 策略 | 实现方式 |
|------|----------|
| 数据库连接池 | SQLAlchemy async + asyncpg 连接池配置 |
| 缓存 | Redis 缓存频繁查询结果 |
| 响应压缩 | `GZipMiddleware` (≥1000 bytes) |
| 异步队列 | Celery + Redis 异步处理通知/报表 |
| 索引优化 | 27 个自定义 Index（覆盖 project/task/audit 等） |
| 前端构建 | Vite 生产构建（tree-shaking + 代码分割） |

## 7. 日志管理

| 日志类型 | 模块 | 存储 |
|----------|------|------|
| 请求日志 | `log_requests` 中间件 | stdout / 文件 |
| 审计日志 | `AuditLog` 表 | 数据库 |
| 应用日志 | `setup_logging` 配置 | `logs/` 目录 |
| Worker 日志 | `queue_worker` | `logs/` 目录 |
| 定时任务日志 | `JobExecutionLog` 表 | 数据库 |

## 8. 备份策略

| 数据 | 备份方式 | 频率 |
|------|----------|------|
| PostgreSQL | pg_dump / Docker volume | 每日 |
| 文件上传 | `uploads/` volume 快照 | 按需 |
| 配置文件 | `.env` 版本控制（加密） | 每次变更 |
