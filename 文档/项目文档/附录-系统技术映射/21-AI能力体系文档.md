# 21 · AI 能力体系文档

> 本系统最核心的差异化能力。基于 通维咨询 知识体系，AI 能力覆盖范围管理、进度管理、风险管理、沟通管理等领域。

---

## 1. AI 总体架构

```
用户输入（自然语言 / 结构化指令）
    ↓
┌─────────────────────────────────────────────┐
│            AI Router (LLM Router)           │
│  根据 Provider 权重/可用性 路由到最佳 LLM    │
└────────────────────┬────────────────────────┘
                     ↓
    ┌────────────────┴────────────────┐
    │          AI 引擎层              │
    │  ai_engine.py  核心调用引擎      │
    │  ai_service.py  业务服务封装     │
    │  自研 LLM Router/Provider（可选 LangChain）   │
    └────────────────┬────────────────┘
                     ↓
    ┌────────────────┴─────────────────┐
    │      AI 能力模块                 │
    ├─ WBS 智能分解                     │
    ├─ 风险自动识别与分析               │
    ├─ Agent 多智能体协同               │
    ├─ RAG 检索增强生成                 │
    ├─ NLP 智能查询                     │
    ├─ EVM/AI 预测                      │
    ├─ 日报/周报自动生成                │
    └─ 自然语言查询 (nlp_query)         │
    └────────────────┬─────────────────┘
                     ↓
        真实回写数据库 (tasks / risks / EVM ……)
```

## 3. AI 核心能力详情

### 3.1 WBS 智能分解（对应 5.4 创建 WBS）

- **接口**：`POST /api/v1/ai/generate-wbs`
- **输入**：自然语言描述项目目标（如"开发一个电商平台，3个月，5人团队"）
- **输出**：
  - 写入 `tasks` 表（含 `wbs_code` / `level` / `parent_task_id` / `estimated_hours`）
  - 同步写入 `risks` 表（自动识别关联风险）
- **AI 技术**：自研 LLM Provider 工作流 + 结构化输出解析（LangGraph 未使用）

### 3.2 风险自动识别（对应 11.2–11.4）

- **触发方式**：WBS 生成时同步；独立风险分析 API
- **能力**：
  - 风险类别分类（TECHNICAL/SCHEDULE/COST/RESOURCE/QUALITY/EXTERNAL/BUSINESS）
  - 概率×影响评分（定性分析）
  - 风险响应策略建议（avoid/mitigate/transfer/accept）
- **存储**：`Risk.ai_analysis` (JSON) 字段

### 3.3 多 Agent 协同（对应 4.3 指导与管理项目工作）

- **接口**：`/api/v1/multi-agent` + `/api/v1/ai/agent`
- **能力**：
  - 多个 AI Agent 并行执行不同子任务
  - 自研 LLM Provider 工作流图编排（LangGraph 未使用）
  - `AgentSession` 追踪会话状态
- **适用**：大型 WBS 的逐层分解、依赖分析、资源优化

### 3.4 RAG 知识库（对应 4.4 管理项目知识）

- **接口**：`/api/v1/knowledge-base`
- **流程**：上传文档 → `KnowledgeDocument` → 切分 `KnowledgeChunk` → 向量化索引 → 语义检索 → 增强生成
- **存储**：PostgreSQL 全文检索（Meilisearch 全文搜索 / Neo4j 图关系 为规划中·未启用组件）
- **用途**：项目规范复用、历史经验引导 AI 决策

### 3.5 NLP 智能查询（对应 5.2 收集需求 / 报告）

- **接口**：`/api/v1/nlp-query`
- **能力**：自然语言查询项目/任务/风险数据（如"所有高风险任务有哪些？""本月成本超支的项目"）
- **实现**：NL2SQL + 语义解析

### 3.6 EVM/AI 预测（对应 6.6/7.4 控制进度/成本）

- **存储**：`EVMSnapshot.ai_predictions` (JSON)
- **能力**：
  - 基于历史 EVM 数据预测 EAC/ETC
  - 异常检测（CPI/SPI 偏差趋势警告）
  - 蒙特卡洛模拟式风险量化

### 3.7 自动日报/周报（对应 10.2 管理沟通）

- **接口**：`/api/v1/reports` + `scheduler_service`
- **能力**：
  - 汇总任务进展/风险状态/EVM 指标
  - 生成中文摘要文本（AI 润色）
  - PDF 导出（reportlab）+ 邮件发送（SMTP）+ 站内通知

## 4. AI 配置管理

| 配置项 | 位置 | 说明 |
|--------|------|------|
| API Key | `backend/.env` | 各 Provider 密钥 |
| 模型选择 | `.env` 中 `*_MODEL` | 如 `gpt-4` / `deepseek-chat` |
| LLM 路由 | `LLMConfig` | 多 Provider 权重/优先级 |
| 降级策略 | 内置 | 主 Provider 失败 → 自动切备用 |

## 5. AI 安全与降级

| 场景 | 行为 |
|------|------|
| 未配置任何 API Key | AI 接口返回 503（Service Unavailable）+ 明确提示 |
| 单 Provider 失败 | 自动路由到下一个可用 Provider |
| AI 输出异常 | 结构化校验不通过 → 返回错误信息，要求重试 |
| 速率限制 | 队列排队 + 指数退避重试 |
