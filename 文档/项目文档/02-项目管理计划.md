# 02 · 项目管理计划（Project Management Plan）

> 过程：**4.2 制定项目管理计划**（整合管理）。本计划是**所有子计划的集成总纲**，定义如何执行、监控与收尾本项目。本系统本身即「项目管理工具」，故本计划同时描述「用本系统管理项目」的方法论。

---

## 1. 计划组成（Component Inventory）

通维咨询 规定项目管理计划包含 **三大基准 + 多项子管理计划 + 项目生命周期选择**。本系统对各组件的落地如下：

### 1.1 三大基准（Baselines）

| 基准 | 系统落地 | 数据模型 |
|------|----------|----------|
| 范围基准 | 范围说明书 + WBS + WBS 词典 | `projects`、`tasks`(wbs_code/parent_task_id)、`epics`、`task_templates` |
| 进度基准 | 进度计划 + 里程碑 | `tasks`(planned_start/planned_end)、`task_dependencies`、`milestones`、`baseline_start/end` |
| 成本基准 | 成本估算 + 预算 | `projects`(budget/baseline_budget)、`budgets`(ProjectBudget/BudgetCategory/CostRecord) |

### 1.2 子管理计划（Subsidiary Plans）

| 子计划 | 对应文档 | 系统支撑 |
|--------|----------|----------|
| 范围管理计划 | 04 | 自定义字段、表单、范围变更经审批流 |
| 需求管理计划 | 04 | `custom_fields`、`forms`、`wiki` |
| 进度管理计划 | 05 | 甘特图服务、依赖、Sprint、EVM 日期 |
| 成本管理计划 | 06 | 预算/实际成本/EVM 快照 |
| 质量管理计划 | 07 | pytest、审批门、合规控制、报表 |
| 资源管理计划 | 08 | 资源/分配/角色/成员 |
| 沟通管理计划 | 09 | 通知/消息/WebSocket/邮件/集成 |
| 风险管理计划 | 10 | 风险登记/量化/AI 分析/预警 |
| 采购管理计划 | 11 | 应用市场/集成/Zapier/Webhook/MCP |
| 干系人参与计划 | 12 | RBAC/成员/审批人/仪表盘 |
| 变更管理计划 | 03/16 | 审批引擎 `approval_engine` + 审计日志 |
| 配置管理计划 | 22 | `.env`、Alembic 版本化、Docker 镜像 |

### 1.3 其他组件

- **生命周期选择**：支持敏捷(`agile`)/瀑布(`waterfall`)/混合(`hybrid`)/看板(`kanban`) —— `ProjectType` 枚举。
- **开发方法**：AI 驱动迭代；后端 TDD（pytest）；前端组件化。
- **管理审查**：仪表盘指标 + 监控指标收集器 `metrics_collector` + 健康检查 `/health`。

## 2. 执行方法（How to Execute）

1. **规划**：用 AI WBS（`/ai/generate-wbs`）快速生成范围与进度草稿 → 人工修订 → 建立基线。
2. **执行**：任务分配 → 自动化规则触发通知/Webhook → Agent 协同推进。
3. **监控**：EVM 快照每日/事件驱动生成，CPI/SPI 偏差超阈报警；监控中间件追踪慢查询。
4. **收尾**：里程碑 `completed` + 项目 `ARCHIVED` + 经验沉淀至 Wiki。

## 3. 变更控制流程（Integrated Change Control）

过程 **4.6 实施整体变更控制**：

```
提出变更 → 记录(AuditLog) → 审批流(ApprovalFlow) → 更新基线(baseline_*) → 通知干系人 → 执行
```

- 数据模型：`approvals`(ApprovalFlow/Instance/Step/Delegate)、`audit_logs`。
- 服务：`approval_engine.py`、`automation_engine.py`。

## 4. 配置与版本管理

- 数据库 schema 演进：`alembic upgrade head`（生产）/ `create_all` 兜底（开发 `DB_MIGRATE=0`）。
- 环境变量：`backend/.env`（由 `.env.example` 复制），含密钥/AI/集成/SMTP。
- 镜像：多阶段 `Dockerfile`（前端构建 + 后端运行），`docker-compose.yml` 编排。

## 5. 绩效测量规则（Measurement）

| 指标 | 公式/来源 | 位置 |
|------|-----------|------|
| 进度偏差 SV | EV − PV | `evm_snapshots.schedule_variance` |
| 成本偏差 CV | EV − AC | `evm_snapshots.cost_variance` |
| CPI | EV / AC | `evm_snapshots.cost_performance_index` |
| SPI | EV / PV | `evm_snapshots.schedule_performance_index` |
| EAC/ETC/VAC/TCPI | 标准 EVM 公式 | `evm_snapshots` |

## 6. 审查与报告节奏

- 实时：仪表盘、WebSocket 推送、站内通知。
- 周期：日报/周报（`/reports`，可 PDF 导出 + 邮件）。
- 审计：合规审计 `ComplianceAudit` 按计划执行。
